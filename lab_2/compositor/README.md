# Компоновщик графических объектов

Лабораторная 2, задание 1, вариант 4. Реализованы модель данных и последовательное
построение изображения на C++20. Исполняемого приложения пока нет.

- `Color` проверяет RGB-компоненты в диапазоне 0–255.
- `Rectangle` хранит геометрию, цвет и приоритет. Размеры положительные,
  координаты и приоритет могут быть отрицательными. Правая и нижняя границы
  исключаются из покрываемой области и вычисляются в 64-битном типе.
- `Scene` — упорядоченный набор прямоугольников с доступом только для чтения.
  Позиция прямоугольника определяет его индекс. Пустой список допустим.
  Размеры холста и начальный цвет в сцене не хранятся.
- `PixelState` хранит цвет и необязательную пару «приоритет, индекс». Отсутствие
  этой пары обозначает фон, не ограничивая допустимые приоритеты.
- `Image` — холст; конструктор заполняет пиксели заданным начальным цветом.
  Он проверяет размеры и координаты, предоставляет чтение
  состояния, получение цвета и замену состояния пикселя целиком.

`setPixel` не выбирает победителя и не является атомарной операцией. Правила
наложения находятся в отрисовке, а мьютексы на области будут в отдельной
политике синхронизации. Модель не зависит от потоков, файлов или окна.

## Последовательная отрисовка

- `RectangleClipper::clip` получает прямоугольник и размеры холста, возвращает
  `std::optional<PixelBounds>`. Границы полуоткрытые: `[left, right) × [top, bottom)`.
  При отсутствии пересечения возвращается `std::nullopt`. Компонент не обращается
  к пикселям; нулевой размер области обрезки означает пустое пересечение.
- `shouldReplace` из `OverlayRule` — чистая функция: фон уступает любому объекту,
  больший приоритет побеждает, при равенстве побеждает больший индекс.
  Одинаковые приоритет и индекс не требуют замены. Функция не меняет состояние.
- `Compositor::render(scene, canvas)` изменяет переданный холст, последовательно обходит
  прямоугольники и пиксели обрезанных областей, применяет правило и записывает
  цвет и метаданные вместе. Входная сцена не меняется, ошибки выделения памяти
  передаются вызывающему коду. Пока требуется холст без прежних победителей.
  Окно, файлы и синхронизация здесь отсутствуют.

Объявления находятся в `include/rendering/`, определения — в `src/rendering/`.
Библиотека `compositor_rendering` зависит от `compositor_model`.

Из корня монорепозитория:

```sh
cmake -S lab_2/compositor -B build/compositor -DCMAKE_BUILD_TYPE=Release
cmake --build build/compositor --parallel
ctest --test-dir build/compositor --output-on-failure
```

Проверки модели, обрезки, правила наложения и композиции не требуют сторонних
библиотек. Для `ctest --test-dir`
нужен CMake 3.20 или новее.
