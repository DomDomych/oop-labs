# Компоновщик графических объектов

Лабораторная 2, задание 1, вариант 4. Реализованы модель данных и последовательное
построение изображения на C++20. Исполняемого приложения пока нет.

- `Color` проверяет RGB-компоненты в диапазоне 0–255.
- `Rectangle` хранит геометрию, цвет и приоритет. Размеры положительные,
  координаты и приоритет могут быть отрицательными. Правая и нижняя границы
  исключаются из покрываемой области и вычисляются в 64-битном типе.
- `Scene` — упорядоченный набор прямоугольников с доступом только для чтения.
  Позиция прямоугольника определяет его индекс. Пустой список допустим.
  Размеры холста и начальный цвет в сцене не хранятся.
- `PixelState` хранит цвет и необязательную пару «приоритет, индекс». Отсутствие
  этой пары обозначает фон, не ограничивая допустимые приоритеты.
- `Image` — холст; конструктор заполняет пиксели заданным начальным цветом.
  Он проверяет размеры и координаты, предоставляет чтение
  состояния, получение цвета и замену состояния пикселя целиком.
  `swap` обменивает размеры и хранилища без выделения памяти и без исключений.

`setPixel` не выбирает победителя и не является атомарной операцией. Правила
наложения находятся в отрисовке, а мьютексы на области будут в отдельной
политике синхронизации. Модель не зависит от потоков, файлов или окна.

## Последовательная отрисовка

- `RectangleClipper::clip` получает прямоугольник и размеры холста, возвращает
  `std::optional<PixelBounds>`. Границы полуоткрытые: `[left, right) × [top, bottom)`.
  При отсутствии пересечения возвращается `std::nullopt`. Компонент не обращается
  к пикселям; нулевой размер области обрезки означает пустое пересечение.
- `shouldReplace` из `OverlayRule` — чистая функция: фон уступает любому объекту,
  больший приоритет побеждает, при равенстве побеждает больший индекс.
  Одинаковые приоритет и индекс не требуют замены. Функция не меняет состояние.
- `RegionGrid` описывает регулярную сетку с заданными шириной и высотой области.
  Размеры положительные, номера областей идут построчно. `bounds(id)` возвращает
  полуоткрытые границы с обрезкой крайних областей, `regionAt(x, y)` — номер области
  пикселя. Проверяются координаты, номера и переполнение числа областей.
  Компонент не хранит пиксели или мьютексы. Компоновщик использует сетку
  для обхода только тех областей, которые пересекает текущий прямоугольник.
- `Compositor(regionWidth, regionHeight)` получает положительные размеры области
  явно; значения по умолчанию не зашиты. `render(scene, canvas)` последовательно
  обходит прямоугольники, пересекаемые области сетки и пиксели их пересечений,
  применяет правило и записывает
  цвет и метаданные вместе. Входная сцена не меняется, ошибки выделения памяти
  передаются вызывающему коду. Приоритет и индекс сравниваются только между
  прямоугольниками текущего вызова. Первый объект текущего вызова, покрывший пиксель,
  заменяет его независимо от прежних метаданных. Непокрытые пиксели сохраняют всё
  состояние. Пустая сцена ничего не меняет.
  Окно, файлы и синхронизация здесь отсутствуют.

### Сохранение холста при ошибке

Для непустой сцены создаётся рабочая копия холста. Все изменения производятся
в ней; после успешного завершения содержимое обменивается с исходным холстом
через `Image::swap`. Любое исключение до обмена оставляет исходные размеры,
цвета и метаданные неизменными. Ошибка передаётся вызывающему коду.
Успешное применение результата инвалидирует прежние ссылки на пиксели.
Пустая сцена не выделяет память и не меняет хранилище.

Цена гарантии — дополнительная копия изображения и линейное время копирования.
Эти расходы относятся к полному времени вызова `render`.

Вызовы для одного холста выполняются последовательно. Временный массив отметок
существует только внутри `render`: один байт на пиксель, инициализация за O(width × height)
для непустой сцены. Он выделяется до изменения холста, не добавляет идентификаторов
в модель и позволяет сохранять старые метаданные непокрытых пикселей. Индекс победителя
относится к сцене того вызова, который последним изменил пиксель; глобальным ID он не является.

```cpp
Image canvas{800, 600, Color{255, 255, 255}};
const Scene first{{Rectangle{0, 0, 100, 100, Color{255, 0, 0}, 10}}};
const Scene second{{Rectangle{50, 50, 100, 100, Color{0, 0, 255}, 1}}};
const Compositor compositor{32, 16}; // Пример настройки, не рекомендуемый оптимум.
compositor.render(first, canvas);
compositor.render(second, canvas); // Синий перекрывает красный: это новый вызов.
```

Разбиение одного набора объектов на несколько вызовов может изменить результат:
приоритеты разных вызовов не сравниваются. Для независимых замеров режимов нужно
использовать одинаково подготовленные холсты.

Размер области не меняет цвета и метаданные результата. Сейчас обход областей
последовательный, без блокировок. На следующем этапе обработка одного пересечения
станет участком, защищаемым мьютексом соответствующей области.

Объявления находятся в `include/rendering/`, определения — в `src/rendering/`.
Библиотека `compositor_rendering` зависит от `compositor_model`.

Из корня монорепозитория:

```sh
cmake -S lab_2/compositor -B build/compositor -DCMAKE_BUILD_TYPE=Release
cmake --build build/compositor --parallel
ctest --test-dir build/compositor --output-on-failure
```

Проверки модели, обрезки, правила наложения, композиции, сетки и сохранности холста
при ошибках выделения памяти не требуют сторонних
библиотек. Для `ctest --test-dir`
нужен CMake 3.20 или новее.
