# Компоновщик графических объектов

Лабораторная 2, задание 1, вариант 4. Реализованы модель данных, последовательное и параллельное
построение изображения на C++20, загрузка конфигурации и консольное сохранение PPM.

- `Color` проверяет RGB-компоненты в диапазоне 0–255.
- `Rectangle` хранит геометрию, цвет и приоритет. Размеры положительные,
  координаты и приоритет могут быть отрицательными. Правая и нижняя границы
  исключаются из покрываемой области и вычисляются в 64-битном типе.
- `Scene` — упорядоченный набор прямоугольников с доступом только для чтения.
  Позиция прямоугольника определяет его индекс. Пустой список допустим.
  Размеры холста и начальный цвет в сцене не хранятся.
- `PixelState` хранит цвет и необязательную пару «приоритет, индекс». Отсутствие
  этой пары обозначает фон, не ограничивая допустимые приоритеты.
- `Image` — холст; конструктор заполняет пиксели заданным начальным цветом.
  Он проверяет размеры и координаты, предоставляет чтение
  состояния, получение цвета и замену состояния пикселя целиком.
  `swap` обменивает размеры и хранилища без выделения памяти и без исключений.
  Копирующее и перемещающее присваивание запрещены; копирующий конструктор сохранён.
  Перемещающий конструктор переносит хранилище без исключений и оставляет источник
  пустым (`0 × 0`). Чтение и запись пикселей пустого объекта выбрасывают
  `std::out_of_range`. Его можно копировать, перемещать, уничтожать и обменивать
  через `swap`; отрисовка на нём отвергается с `std::invalid_argument`, в том числе
  для пустой сцены. Обычный конструктор по-прежнему запрещает нулевые размеры.

`setPixel` не выбирает победителя и не является атомарной операцией. Правила
наложения находятся в отрисовке, а мьютексы на области — в отдельной
политике синхронизации. Модель не зависит от потоков, файлов или окна.

## Загрузка конфигурации

`JsonConfigLoader::load(path)` читает JSON и возвращает `RunConfig`: настройки
холста, настройки исполнения, `Scene` и абсолютный путь результата.
Пример полного документа: `configs/example.json`. Все показанные поля обязательны;
неизвестные поля отклоняются. Для целых параметров не допускаются дробные числа,
строки или логические значения. Размеры и число потоков положительны; цвета —
три целых компонента 0–255. Координаты и приоритеты могут быть отрицательными.
Пустой массив прямоугольников допустим, порядок записей сохраняется.

Режимы: `sequential`, `parallel-unsafe`, `parallel-safe`. Поле `threads` задаёт
число работников для параллельных режимов; последовательному исполнителю оно
не требуется, но остаётся обязательной частью конфигурации для смены режима.
Относительный `output.image` разрешается от папки конфигурационного файла,
а не от текущего каталога процесса. Загрузчик не создаёт холст, потоки, каталоги
или выходной файл. Доступность пути для записи проверит будущий экспортёр.
Ошибки чтения и проверки сообщаются через `std::runtime_error` с именем файла;
ошибки полей содержат путь, например `rectangles[0].color[1]`.

Для сборки модуля ввода нужна библиотека Boost.JSON (Boost 1.75 или новее,
пакет разработки с CMake-конфигурацией). Она используется только внутри `.cpp`;
публичные заголовки и модель от Boost не зависят. Asio не используется.
Приложение принимает ровно один аргумент — путь к конфигурации.

## Запуск и сохранение

После сборки из корня репозитория:

```sh
./build/compositor/compositor lab_2/compositor/configs/example.json
```

Пример сохранит `lab_2/compositor/configs/result.ppm`. Путь результата разрешается
от папки конфигурации. Существующий файл заменяется; родительская папка должна
существовать. Выходные коды: `0` — успех, `1` — ошибка загрузки/выполнения/записи,
`2` — неверное число аргументов. Ошибки выводятся в stderr.

`main` связывает загрузчик, `PpmWriter` и `RenderApplication`. Приложение получает
`IImageWriter` по ссылке (экспортёр должен жить дольше приложения), создаёт холст
и компоненты выбранного режима, вызывает композитор и сохраняет результат.
Сохранение выполняется только после успешной композиции. Подстановка другого
экспортёра не требует менять прикладной слой.

`PpmWriter` записывает бинарный P6: заголовок и RGB-байты построчно без метаданных
приоритетов. Временный файл создаётся в служебной папке рядом с назначением;
после успешной записи и закрытия файла выполняется rename. При ошибке до замены
старый результат сохраняется, временные данные удаляются через RAII. Это защита
от ошибок выполнения, а не гарантия сохранности при отключении питания.
Мьютексы областей во время экспорта не нужны: все задания уже завершены.
Незащищённый режим при пересечениях по-прежнему допускает data race и UB.

Окно изображения, бенчмарки и отчёты о производительности пока не реализованы.

## Организация отрисовки

- `RectangleClipper::clip` получает прямоугольник и размеры холста, возвращает
  `std::optional<PixelBounds>`. Границы полуоткрытые: `[left, right) × [top, bottom)`.
  При отсутствии пересечения возвращается `std::nullopt`. Компонент не обращается
  к пикселям; нулевой размер области обрезки означает пустое пересечение.
- `shouldReplace` из `OverlayRule` — чистая функция: фон уступает любому объекту,
  больший приоритет побеждает, при равенстве побеждает больший индекс.
  Одинаковые приоритет и индекс не требуют замены. Функция не меняет состояние.
- `RegionGrid` описывает регулярную сетку с заданными шириной и высотой области.
  Размеры положительные, номера областей идут построчно. `bounds(id)` возвращает
  полуоткрытые границы с обрезкой крайних областей, `regionAt(x, y)` — номер области
  пикселя. Проверяются координаты, номера и переполнение числа областей.
  Компонент не хранит пиксели или мьютексы и не зависит от `RectangleClipper`.
  Общий геометрический тип находится в `rendering/PixelBounds.hpp`.
- `Compositor(regionWidth, regionHeight, executor, accessPolicy)` получает положительные размеры области
  явно; значения по умолчанию не зашиты. `render(scene, canvas)` проверяет холст,
  создаёт рабочую копию, передаёт обработку прямоугольников исполнителю и применяет результат
  только после успеха. Входная сцена не меняется, ошибки выделения памяти
  передаются вызывающему коду. Приоритет и индекс сравниваются только между
  прямоугольниками текущего вызова. Первый объект текущего вызова, покрывший пиксель,
  заменяет его независимо от прежних метаданных. Непокрытые пиксели сохраняют всё
  состояние. Пустая сцена ничего не меняет.
  Компоновщик не создаёт потоки и не захватывает мьютексы. Исполнитель и политика
  передаются по ссылке, должны жить дольше компоновщика и выбираться снаружи.
- Внутренний `detail::RectanglePainter` обрабатывает один прямоугольник за вызов
  `paint`: делегирует обрезку `RectangleClipper`, использует `RegionGrid` для обхода
  областей и `OverlayRule` для выбора победителя. Он владеет сеткой, состоянием доступа к областям и отметками
  текущего запуска, изменяет только рабочую копию и не управляет её применением.
  Один обработчик живёт в пределах одного `render`, до обмена хранилищ.
  Объявление и определение находятся в `src/rendering/`, это не публичный API.

### Сохранение холста при ошибке

Для непустой сцены создаётся рабочая копия холста. Все изменения производятся
в ней; после успешного завершения содержимое обменивается с исходным холстом
через `Image::swap`. В безопасных режимах любое исключение до обмена оставляет исходные размеры,
цвета и метаданные неизменными. Исполнитель сначала дожидается всех задач,
затем передаёт исключение вызывающему коду. Незащищённая параллельная запись
может приводить к UB; для неё гарантия сохранности холста не действует.
Успешное применение результата инвалидирует прежние ссылки на пиксели.
Пустая сцена не выделяет память и не меняет хранилище.

Цена гарантии — дополнительная копия изображения и линейное время копирования.
Эти расходы относятся к полному времени вызова `render`.

Вызовы для одного холста выполняются последовательно. Временный массив отметок
принадлежит обработчику текущего `render`: один байт на пиксель, инициализация за O(width × height)
для непустой сцены. Он выделяется до изменения холста, не добавляет идентификаторов
в модель и позволяет сохранять старые метаданные непокрытых пикселей. Индекс победителя
относится к сцене того вызова, который последним изменил пиксель; глобальным ID он не является.

```cpp
Image canvas{800, 600, Color{255, 255, 255}};
const Scene first{{Rectangle{0, 0, 100, 100, Color{255, 0, 0}, 10}}};
const Scene second{{Rectangle{50, 50, 100, 100, Color{0, 0, 255}, 1}}};
ParallelExecutor executor{4}; // Переиспользуется между вызовами.
const RegionMutexPolicy accessPolicy;
const Compositor compositor{32, 16, executor, accessPolicy};
compositor.render(first, canvas);
compositor.render(second, canvas); // Синий перекрывает красный: это новый вызов.
```

Разбиение одного набора объектов на несколько вызовов может изменить результат:
приоритеты разных вызовов не сравниваются. Для независимых замеров режимов нужно
использовать одинаково подготовленные холсты.

В безопасных режимах размер области не меняет цвета и метаданные результата.
`RectanglePainter` передаёт обработку полного пересечения в `withRegion`.
Политика с мьютексами защищает одновременно `touched`, проверку победителя и запись
состояния. Обработка не удерживает более одного мьютекса области.

## Исполнение и режимы

| Исполнитель | Политика | Режим |
|---|---|---|
| `SequentialExecutor` | `NoLockPolicy` | Последовательный |
| `ParallelExecutor` | `NoLockPolicy` | Экспериментальный, возможны гонки данных и UB |
| `ParallelExecutor` | `RegionMutexPolicy` | Параллельный с защитой областей |

`IExecutor::execute(count, task)` выполняет задачу для индексов `[0, count)`.
Задачи могут выполняться одновременно и в произвольном порядке. Исполнитель
не сохраняет callable после завершения серии. При исключении задачи остальные
индексы всё равно обрабатываются; после завершения всей серии передаётся первое
сохранённое исключение. Оба исполнителя имеют одинаковую семантику ошибок.
Пустой callable запрещён, нулевое количество заданий допустимо.

`ParallelExecutor` содержит постоянный пул `std::jthread`. Работники ожидают новую
серию через `std::condition_variable` и динамически получают индексы через атомарный
счётчик. Число работников задаётся конструктором; по умолчанию используется
`hardware_concurrency()`, при нулевом результате — один поток. Нулевое явно заданное
число потоков запрещено. Вызовы `execute` сериализуются. Рекурсивный вызов этого же
исполнителя из его задачи не поддерживается. Уничтожать исполнитель одновременно
с его использованием нельзя. При уничтожении ожидающие работники пробуждаются,
выходят из цикла, после чего `jthread` присоединяет потоки.

`IRegionAccessPolicy` создаёт отдельное состояние доступа для каждого `render`.
`withRegion` выполняет переданную операцию синхронно, не сохраняет её и передаёт
исключения наружу. `RegionMutexPolicy` освобождает блокировку через RAII даже при
ошибке. `NoLockPolicy` не обещает потокобезопасности. Служебная синхронизация пула
присутствует и в небезопасном режиме; защита пикселей в нём отключена.

Исполнитель знает только индексы и callable, политика доступа — номера областей
и callable. Они не зависят от `Image`, `Scene` или правил наложения.

Объявления находятся в `include/rendering/`, определения — в `src/rendering/`.
Библиотека `compositor_rendering` использует `compositor_model`,
`compositor_execution` и `compositor_access`.

Из корня монорепозитория:

```sh
cmake -S lab_2/compositor -B build/compositor -DCMAKE_BUILD_TYPE=Release
cmake --build build/compositor --parallel
ctest --test-dir build/compositor --output-on-failure
```

Проверки модели, обрезки, правила наложения, композиции, сетки и сохранности холста
при ошибках выделения памяти не требуют сторонних
библиотек. Для `ctest --test-dir`
нужен CMake 3.20 или новее.

Проверки пула охватывают реальное одновременное выполнение, повторные серии,
ошибки задач и повторное использование после ошибки. Безопасная параллельная
отрисовка сравнивается с последовательной для разных чисел потоков и размеров
областей. Отдельно внедряется ошибка после записи рабочей копии и проверяется
сохранность исходного холста. Незащищённый режим тестируется только на
непересекающихся объектах: намеренное UB не входит в проверку корректности.
