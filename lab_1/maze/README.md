# Генерация и прохождение лабиринта

Лабораторная работа по ООП, задание 2, вариант 2.
Консольная программа на C++20 создаёт лабиринт и находит путь между двумя клетками.
Для генерации используется поиск в глубину (DFS), для поиска пути — поиск в ширину (BFS).

## Сборка и запуск

Готовую версию для Windows x64 можно скачать в
[Releases](https://github.com/DomDomych/maze/releases).
Распакуйте ZIP: `run.cmd` запускает меню, `examples.cmd` — два примера,
`tests.cmd` — тесты. Компилятор, CMake и GoogleTest устанавливать не нужно.

Нужны CMake 3.16 или новее и компилятор с поддержкой C++20.

```sh
cmake -S . -B build
cmake --build build
./build/maze
```

В меню выберите генерацию, введите размеры лабиринта, затем координаты начала
и конца пути. Координаты вводятся как `строка столбец`, начиная с нуля.

Обозначения: `#` — стена, `.` — путь, `S` — начало, `E` — конец,
`B` — начало и конец совпадают.

Готовые примеры без ввода: `./build/maze_example`.
Программа показывает лабиринты 5 × 5 и 4 × 7 клеток и пути через них.
При сборке скриптами: `./build/Debug/maze_example`.

## Тесты

После сборки:

```sh
cd build
ctest --output-on-failure
```

Используется GoogleTest. Если он не установлен, CMake скачает его при первой
сборке — потребуется интернет.

## Скрипты для Linux

```sh
./scripts/build.sh         # Сборка Debug
./scripts/build.sh Release # Сборка Release
./scripts/run.sh           # Сборка и запуск
./scripts/test.sh          # Сборка и запуск тестов
./scripts/format.sh        # Форматирование кода (нужен clang-format)
```

Скрипты `build.sh`, `run.sh` и `test.sh` принимают `Debug` или `Release`.
Результаты сборки находятся в `build/Debug` или `build/Release`.

## Структура

- `core/` — хранение клеток и проходов, генерация и поиск пути.
- `cli/` — меню, ввод и вывод лабиринта.
- `tests/` — модульные и интеграционные тесты.

## Модель данных

`Grid<T>` владеет клетками: они хранятся по значению в `std::vector`.
Тип `T` задаёт данные клетки. Алгоритмы не используют эти данные для обхода.
Проходы соединяют только клетки с общей стороной и работают в обе стороны.
Каждый проход хранится один раз; координаты проверяются перед доступом.

Генератор создаёт связный лабиринт без циклов: между любыми двумя клетками
существует ровно один простой путь. Размеры лабиринта измеряются в клетках,
а стены занимают дополнительные символы при выводе.
